## Delivery rules

- Preserve the original rubric, CSV, and reviewed writing in SUBMISSION.md. The fictional date is October 5, 2026.
- The rubric allows about three hours and says stop at four. Record actual elapsed work. Unknown history prevents a compliance claim; another audit does not restart the allowance.
- Add no unit tests, mocks, fake successful actions, or redundant CI. Check real affected workflows and retain the type/build check.
- Keep React, Vite, TypeScript, shadcn controls, TanStack Router and Query, and Zod. Add no backend or runtime agent for this submission.
- Router owns selection and view. Query owns the loaded snapshot and save lifecycle. Native forms own drafts. Pure functions derive policy. CSS owns layout.
- Author no useState/useEffect or shadow store for those responsibilities. A genuinely necessary exception requires a concrete case and observed behavior.
- Keep one status enum, one save owner, and one versioned localStorage edits document. The supported scope is one browser/origin and active editing tab.
- Preserve source facts. A status or note never proves a sent reply, warehouse receipt, carrier filing, shipment, or refund.
- Use one writer and bounded read-only reviewers. No recursive delegation or automatic merge. Keep findings concrete and rerun affected paths after a correction.
- Use the permitted browser capability. Preserve exact evidence provenance and mark unavailable checks unverified. Do not work around browser policy.
- Follow [skills-and-review.md](docs/skills-and-review.md). Generic skill test defaults do not override the no-unit/no-mock instruction.
- Keep documentation specific. Current status belongs in completion.md, acceptance in rubric-audit.md, and actual executed results in docs/evidence.
- The applicant records their own natural voice. Never substitute generated speech or a placeholder link.
- Keep hiring correspondence, personal availability, and raw session transcripts out of this public repository.
- Repository cleanup does not authorize sending messages or the final application. Keep artifact readiness separate from actual delivery.

Use the default-branch README commands. `npm run build` includes TypeScript checking. Preserve closed technical issues; keep #5 open until the complete accessible PDF exists and #1 open until final delivery is confirmed.
